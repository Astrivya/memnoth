# @astrivya/mcp

Launcher for the [memnoth](https://github.com/astrivya/memnoth) MCP server.

The release package bundles the server binary in `vendor/<platform>-<arch>/memnoth-mcp`
(`memnoth-mcp.exe` on Windows) for five targets: `win32-x64`, `linux-x64`, `linux-arm64`,
`darwin-x64`, and `darwin-arm64`. The release workflow extracts these binaries from the
checksummed CLI archives and runs the Linux binary's MCP self-test before publishing.
The launcher resolution order is:

1. **Bundled binary** (`vendor/<platform>-<arch>/memnoth-mcp`) — most hermetic, works offline
2. **`MEMNOTH_BIN` environment variable** — explicit override for unusual install locations
3. **`memnoth` on `PATH`** — what `cargo install` and release installers produce

If no bundled binary is present for this platform, it falls back to `MEMNOTH_BIN` then `PATH`.

## Install

```bash
npx -y @astrivya/mcp --help    # sanity check that the launcher starts the bundled server
```

The published package ships the binary, so no separate Memnoth install is required. Set
`MEMNOTH_BIN` to use a different build (for example a locally compiled one). The release
workflow needs the repository's `NPM_TOKEN` secret to publish; without it, the verified
tarball is attached to the GitHub release for manual publication.

## Client config

This is a standalone stdio server for MCP hosts such as OpenCode, Codex, Claude
Code, Cursor, and Zed. Use the host's local MCP server configuration format.
The default profile is `memory`; the example starts read-only:

```json
{
  "mcpServers": {
    "memnoth": {
      "command": "npx",
      "args": ["-y", "@astrivya/mcp"],
      "env": {
        "MEMNOTH_MCP_PROFILE": "memory",
        "MEMNOTH_MCP_READ_ONLY": "1"
      }
    }
  }
}
```

For OpenCode, use the corresponding `mcp.servers` entry with `type: "local"`,
`command: ["npx", "-y", "@astrivya/mcp"]`, and the same values under
`environment`. The CLI can create and verify a project-scoped entry for you:
`memnoth mcp add --local --clients opencode`.

The published package includes the server binary for supported platforms, so
the Memnoth CLI is optional. Set `MEMNOTH_MCP_DB` to select a specific vault.

## Offline version check

```bash
npx -y @astrivya/mcp --version
# 0.1.0-beta.2
```

The `--version` flag works completely offline without spawning the binary.

**The profile tool counts are generated by** `scripts/check_surface.py` **from** `TOOL_PROFILES` — they are regenerated, not hand-written.
| `MEMNOTH_MCP_PROFILE` | Tools | What it is for |
|---|---|---|
| `memory` | 21 | The vault, the temporal quartet (`vault_history`, `vault_asof`, `vault_contradictions`, `vault_top`), vault hygiene (`mem_duplicates`), index health |
| `code` | 26 | Code-graph navigation plus the filesystem/git toolbox |
| `coord` | 11 | Multi-agent claims, tasks, messaging |
| `micro` | 4 | Smallest useful set |
| `full` | 51 | Everything (default) |

A tool you expected but cannot see is a profile setting, not a missing
capability — the server reports the active profile and its tool count in the
`server/discover` instructions.
