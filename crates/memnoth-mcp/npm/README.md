# @astrivya/mcp

Launcher for the [memnoth](https://github.com/amruthjakku/memnoth) MCP server.

**This package bundles the server binary** in `vendor/<platform>-<arch>/memnoth-mcp`
(`memnoth-mcp.exe` on Windows; six targets: `win32-x64`, `win32-arm64`, `linux-x64`,
`linux-arm64`, `darwin-x64`, `darwin-arm64`). The release `SHA256SUMS` covers those exact
bytes, and the npm verification step runs the launcher against the bundled binary before
the package is published.
The launcher resolution order is:

1. **Bundled binary** (`vendor/<platform>-<arch>/memnoth-mcp`) — most hermetic, works offline
2. **`MEMNOTH_BIN` environment variable** — explicit override for unusual install locations
3. **`memnoth` on `PATH`** — what `cargo install` and release installers produce

If no bundled binary is present for this platform, it falls back to `MEMNOTH_BIN` then `PATH`.

## Install

```bash
npx -y @astrivya/mcp --help    # sanity check that the launcher starts the bundled server
```

The package ships the binary, so no separate memnoth install is required. Set
`MEMNOTH_BIN` to use a different build (for example a locally compiled one).

## Client config

```json
{
  "mcpServers": {
    "memnoth": {
      "command": "npx",
      "args": ["-y", "@astrivya/mcp"],
      "env": { "MEMNOTH_MCP_PROFILE": "full" }
    }
  }
}
```

## Offline version check

```bash
npx -y @astrivya/mcp --version
# 0.1.0-beta.1
```

The `--version` flag works completely offline without spawning the binary.

**The profile tool counts are generated by** `scripts/check_surface.py` **from** `TOOL_PROFILES` — they are regenerated, not hand-written.
| `MEMNOTH_MCP_PROFILE` | Tools | What it is for |
|---|---|---|
| `memory` | 21 | The vault, the temporal quartet (`vault_history`, `vault_asof`, `vault_contradictions`, `vault_top`), vault hygiene (`mem_duplicates`), index health |
| `code` | 26 | Code-graph navigation plus the filesystem/git toolbox |
| `coord` | 11 | Multi-agent claims, tasks, messaging |
| `micro` | 4 | Smallest useful set |
| `full` | 51 | Everything (default) |

A tool you expected but cannot see is a profile setting, not a missing
capability — the server reports the active profile and its tool count in the
`initialize` instructions and in `server/discover`.
